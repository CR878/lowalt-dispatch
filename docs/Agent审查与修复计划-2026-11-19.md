进一步的代码检查还发现以下需要回归覆盖的情况。

- 工具意图裁剪只检查当前 text，“3”“P1”“上午十点”这类追问答复会被视为不需要任务工具。应结合本轮待确认任务和历史上下文验证。

- 前端停止接收后，服务端 worker 仍可能完成已经开始的工单写入。需要明确取消发生在落盘前还是落盘后，并让重试能够找到原结果。

- live 状态工具读取浏览器传入的遥测快照。作为前端辅助说明可以保留来源标记，涉及可执行任务的校验应使用服务端读到的遥测。

**第一批，修复确认、权限与重复写入**

涉及 `services/assistant/models.py`、`engine.py`、`tools.py`、`intake.py`、`app.py` 与前端确认卡和请求协议。

1. 将确认卡的结构化字段提交给服务端，保留完整 ISO 时间、起终点坐标、载荷和优先级。聊天文本用于显示与理解，落盘参数以用户确认的结构化字段为准。
2. 在服务端记录待确认内容及摘要，将确认操作绑定对应内容。模型修改载荷、时间或坐标后，原确认失效，返回更新后的确认卡。
3. 在 Engine 统一执行入口校验本轮允许的工具名称。非法调用返回结构化拒绝结果，相关业务函数不被执行。
4. 为工单创建增加幂等处理，关联用户、request_id 与确认内容。同一请求重放返回原 intake_id，同一标识下内容冲突时返回明确错误。
5. 优先复用现有 IntakeStore 的文件写入与进程内锁实现当前单进程语义。多进程部署时再将唯一约束迁移到已有 SQLite 基础设施。

验收用例覆盖用户拒绝但模型伪造确认、确认后改坐标、隐藏工具调用、连续点击、网络失败后重试、并发提交。每次验收核对 HTTP/NDJSON、工单文件数量和实际保存字段。

第一批完成条件为未确认的请求不新增工单，同一已确认操作只新增一张工单，工具执行范围与 schema 一致。

**第二批，修复时间、草稿与天气的一致性**

涉及 `tools.py`、`evidence.py`、`intake.py`、`ClarificationCard.tsx`。

1. 把日期解析统一为带时区的结果，支持已有中文日期表达中的年份、上午/下午、时分。解析时注入可控的 now，覆盖跨年与日期无效情况。
2. 确认卡直接提交所选年月日和时刻。默认时间只用于尚未给出时刻的待确认建议，用户给出的时刻必须保留。
3. 删除 update_task_draft 的结果缓存。plan_task_preview 的结果缓存需包含草稿摘要，修改草稿时清理旧结果。
4. 天气响应加入 requested_point、目标时刻、有效时刻和抓取时间。建单只复用与当前参数匹配的证据，否则重新查询或记录 unavailable。
5. 追问处理结合待确认任务状态，覆盖只回复重量、优先级、时间和“就按这个位置”的情况。

验收至少包括载荷 1→2→1、预览后修改终点、明天下午 3 点、带年份的跨年日期、两个地点不同时间的天气混用、服务超时与用户改时间。核对用户确认值、工具返回值和落盘值完全一致。

**第三批，修复知识库引用并验证检索质量**

涉及 `knowledge.py`、`rag.py` 与现有知识库测试。

1. 让切片长度与来源行号同时受控。代码块过长时按原文行切分，保留章节和必要的代码块上下文。展示文字与引用正文分别处理。
2. 去掉 rag.search 的简单字符截断，或在确需截断时同步计算实际来源范围。
3. auto 模式先查关键词。对于有充分依据的精确术语问题直接使用命中结果，弱命中或无命中再补向量候选。向量失败时显示实际降级状态。
4. 用固定小型问题集评估 ACK 语义、任务阶段、真实与仿真边界、启动步骤、同义改写和无答案问题。每题保存期望文档及原文范围，逐项记录命中与拒答情况。
5. 根据评估再决定是否更换中文 embedding，现有 Chroma 可以继续复用。索引变更后验证新片段与旧片段的替换结果。

验收重点为每条引用都能用文件版本和行号还原，普通 ACK 问题不因 Chroma 冷启动被拖慢，无依据问题返回明确的 no_match。

**第四批，修复预算、异常恢复与图表**

涉及 `engine.py`、`app.py`、`Assistant.tsx`、`ChartBlock.tsx` 与工单概览工具。

1. 统一 5 轮响应与 8 次工具预算的退出行为，保留已有工具证据，明确尚缺的结果。重复的只读调用在预算内复用结果。
2. 引入单回合总耗时预算和取消信号，在开始下一个工具及写入前检查。已经完成落盘的操作可通过 request_id 找回。
3. 三个工具先保留现有执行方式。仅在测量证明顺序执行导致超时，且工具互不依赖时，再对只读调用增加并发。
4. 图表仅接受合法有限数值。缺失值不转换成 0。饼图正确处理唯一分类、全零、负值和多分类图例，折线保持数据顺序与数值符号。
5. 工单概览明确样本范围与数量，图表展示来源和时间。图表数据优先由工具的结构化结果构建，缩小模型改写数值的机会。

验收覆盖 5 轮耗尽、8 次调用耗尽、第三方超时、主动停止、停止后重试、仅一种状态的饼图、12 分类饼图及缺失值。
