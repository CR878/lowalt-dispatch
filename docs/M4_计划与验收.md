## 3. 写死的语义（测试守着）

1. **去重**：同一 `command_id` 只执行一次。重复投递（MQTT QoS1 可能重复）返回**原来那条 ACK**，不重新执行。
2. **内容冲突**：同一 `command_id` 携带不同 `task_id`/`plan_version`/`payload` → 拒绝并记审计，不覆盖原记录。
3. **过期**：`now >= expires_at` → `accepted=false`，`reject_reason="expired"`，不执行。
4. **未来命令**：`now < issued_at` → 拒绝（`not_yet_valid`）。
5. **任务一致性**：ACK 的 `task_id`/`plan_version` 必须与命令逐字一致。
6. **ACK 不等于完成**：`accepted=true` 只表示"执行端接下了"，`fc_mode` 是飞控模式原样透传，不能解释为"已送达"。
7. **遥测**：每条 `ExecutionObservation` 必须带 `task_id`、`accepted_command_id`、`state.executing_plan_version`；`provenance.is_simulated=True`（SITL / Fake 都算仿真）。
8. **坐标**：`Position.frame=enu_m` 不下发给真实 MAVSDK——ENU 原点未定，转换就是猜。`MavsdkExecutor` 遇到 ENU 直接 `NotImplementedError` 并指向契约文档。
9. **断连**：复用 `agent/link.py` 的 `CloudLinkMonitor` 判云端链路；断连时**不重发命令、不改飞控模式**，只允许按已缓存且仍有效的方案执行。这是"本地备用方案切换"，不是"边缘实时重规划"。
10. **恢复**：进程重启后，已接受但未完成的命令从 SQLite 读回，**不重新执行**，进入 `recovering` 状态等对账。
