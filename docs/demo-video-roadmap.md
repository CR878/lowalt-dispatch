# AERIS 竞赛演示视频基础路线

版本 1.0 · 2026-11-23 · 面向产品、算法、前端、三维与剪辑同学。交付标准见[项目全局约定](../AGENTS.md)。

## 1. 从评委最后记住的一句话倒推

**“AERIS 在给应急物资规划航线时，就会检查沿途是否还留有可达的备降点。通信退化后，调度台还能解释边缘端选择了哪个备用方案。”**

以一单从「中心物资站」送往「河东救援点」的应急配送贯穿全片。地点都是虚构场景内的站名。片尾停在任务复盘界面，让评委看到初始任务、方案选择、异常时刻和最终处置。这样倒推，必拍功能只有六项：任务理解与确认、三维空域、候选航线与备降余量、独立校验、合成执行与异常处置、任务复盘。CR30 给这张任务单一个具体的执行对象。

建议制作 3 分钟、16:9 横屏母版，用 1080p、30 fps 作为团队首轮录制规格。时长、规格和下文的工作日数是可调整的制作预算，正式导出时核对当届提交页面。每段保留独立素材，便于压缩片长。

## 2. 三分钟成片分镜

| 时间 | 观众看到和听到什么 | 制作办法与通过条件 |
|---|---|---|
| 00:00–00:12 | 冷开场。飞机处在河面上方，前方航段亮起琥珀色，画面停住。旁白问「现在通信中断，这架飞机还能落到哪里？」拉高机位，露出备降点，随后回到任务开始。 | 用后半段同一场景制作开场，只多做一次冻结和拉远。危机、飞机、备降点在同一屏可辨。 |
| 00:12–00:32 | 调度员输入「把这批应急物资从中心物资站送到河东救援点」。助手补问重量，生成任务卡。点击确认，地图上两个站点同时亮起。 | 复用助手确认卡。两轮对话可编排，确认按钮要推进任务状态。重量、地点、任务编号在后续画面沿用。 |
| 00:32–00:52 | 地图从正射图倾斜到三维。起点的 CR30 与机型卡相呼应，镜头沿河道前进，一次展示建筑、配送点和备降点。 | 用本地城市和固定运镜。英雄机位可预渲染，地图上用低精度模型。保留地标，使观众换视角后仍认得方位。 |
| 00:52–01:35 | 核心镜头。先画几何候选，再沿路线移动一个采样点。下方曲线光标与地图同步，显示该处可达备降点与剩余余量。一个触及约束的候选被剪枝，随后出现所选方案及独立校验结论。 | 用同一组仿真输入导出候选、剖面和校验记录。镜头在关键点停留，让观众能指出「哪段、什么原因、系统作了什么决定」。无可行路线时按第 3 节处理。 |
| 01:35–02:22 | 点击「开始仿真」。飞机、进度和仪表开始移动。通信退化时清楚显示最后可用状态。地图突出已缓存备用路线和对应备降点，事件栏依次给出退化、选择依据和处置结果。 | 以一个回放时钟驱动地图、遥测和事件。异常按预设时刻触发。缓存选择可重放现有 fixture 的决策，面板注明「情景回放」。留出几秒看清切换前后的路线。 |
| 02:22–02:48 | 飞机抵达所选备降点，时间线收束到「仿真备降完成，物资待接续」。点击退化事件可回看当时位置和路线版本。 | 回放终点、任务卡与审计摘要必须相同。如果剧本采用备降，目的地送达状态保持待接续。 |
| 02:48–03:00 | 回到全景，只保留规划、校验、边缘处置三个节点，结束语「每一次航线选择，都能回到当时的依据」。 | 从上一镜的记录提取节点。片尾注明「虚拟城市 · 示例机型 · 仿真演示」。 |

**最值得做一次设计评审的是 00:52–01:35。** 粗剪时先关掉声音，请一位没参与项目的人指出哪一段路线出了问题、飞机还能落在哪里、系统接受或拒绝了什么。答不出来，就放大采样点、简化曲线、延长停顿，再增加解释文案。

**规划镜头的选例要先于美术锁图。** 当前 `demo-scene.json` 标记为 S1-01 的普通 A* 几何路线。仓库记录过该例在示例机型下被约束拒绝。先在选定版本重跑，选一个确实可通过独立校验的输入作主任务，另取一个可复现的拒绝输入作对照。如果同一任务的几何线和约束线实际重合，就保留相同几何，在采样点展示余量；拒绝案例以明确标注的「对照回放」插入。如果需要同单前后对比，可以让调度员明确修改输入，再展示新一轮结果。画面中的两条折线、余量数字和通过状态均以各自记录为准。

**边缘镜头区分两种输出。** 现有 `agent.demo` 有缓存选择情景。[M2 适配器](../agent/planning.py)说明当前正式校验仅覆盖从任务起点出发的完整航线。预制的途中备降用「备用方案情景回放」呈现。若要在旁白中声明已经按当前位置完成剩余航段校验，需先取得相应实现及本次运行记录。

## 4. 最少要补的连接

1. **固定一份拍摄场景。** 在控制台准备演示场景记录，包含任务信息、虚拟站点坐标、候选及其来源、采样剖面、路线版本、遥测帧、事件时间和章节起点。地图、工单和复盘共同读取。每条记录区分算法运行输出、情景脚本和镜头装饰。
2. **补一个录制入口。** 从现有控制台进入「竞赛演示」，直接加载本地场景。提供开始、暂停、重置、跳章和隐藏录制控件。将确认、异常、选择备用方案、结束四个动作分别绑定到可见反馈，方便一次只重拍一个失误镜头。
3. **用一条时间轴组织前端。** 一个当前时间决定飞机位置、当前航线版本、曲线光标和事件选中项。切换方案时从切换点接续，避免模型跳回起点。备降完成后冻结遥测并生成复盘。
4. **把科技感花在信息变化上。** 深石墨色城市、较低对比度的街区轮廓，青色表示当前方案，琥珀色表示需关注，红色只标被拒绝的具体航段。颜色同时配合虚实线和文字。相机从任务单滑向地图、再沿航线下压到机身；告警亮起时固定相机，让观众看清原因。片中字幕与关键数值在普通笔记本全屏观看时可读。

## 5. 从今天到交片的制作顺序

按三个角色并行排期，可一人兼任。D1 是团队实际开工日，D7 是内部目标交片日。

| 时间 | 算法与场景 | 控制台与三维 | 导演与剪辑 | 到点可交的东西 |
|---|---|---|---|---|
| D1 定故事 | 重跑候选场景，选定通过例和拒绝例 | 试载本地地图和 CR30，固定两站一备降点 | 写临时旁白，在静帧上试排 180 秒 | 一张分镜表、带来源的结果、可播放的粗分镜 |
| D2 打通状态 | 导出场景与事件，记录输入版本 | 实现确认、路线、退化、备降、复盘和重置 | 以未美化界面录一次全流程 | 第一条可从头看到尾的粗录 |
| D3 做核心镜头 | 核对余量、拒绝原因和事件时间 | 做采样点与曲线联动、三机位、备用线切换 | 锁定核心镜头停留时间，做静音盲看 | 单独播放也能看懂的规划与处置两段 |
| D4 精修画面 | 复核最终入镜的所有数字 | 完成模型光照、地图层级、字号、转场和片尾 | 录临时配音与提示音，调画面节奏 | 美术、旁白、字幕统一的样片 |
| D5 正式录制 | 固定代码版本与场景文件 | 在录制机离线连跑三次，再按章录无控件素材 | 录主镜头和备用角度，单独保存干净音轨 | 可独立替换的分镜素材、一次完整长录 |
| D6 粗剪复核 | 逐句核对技术表述 | 修掉遮挡、卡顿、模型跳位 | 完成配音、字幕、混音，请首次观看者复述 | 一版完整成片和最后的返修清单 |
| D7 封版 | 留存入镜结果及来源 | 仅重拍返修镜头 | 核对官方提交规格，导出并从头回看实际文件 | 提交版 MP4、可复剪工程、对应场景版本 |

若时间缩短，先保住确认建单、三维地图、规划解释、异常处置与复盘五段。可先剪掉模型爆炸、远景交通和云架构动画。录制机表现不佳时，可分别高质量录制地图和面板，再按同一时间码合成。

## 6. 最后验收

- **叙事**：第一次观看的人能说出物资从哪出发、为什么选这条路线、通信退化后最终落在哪里。
- **功能**：点击确认、开始仿真、选择事件、重置各有可见结果。重放同一场景三次，任务、曲线、切换时刻和结果一致。
- **三维**：三种机位下地标可认，路线没有穿过用于表达约束的建筑，备降点在镜头内。飞机朝向、运动方向、路线版本匹配。
- **证据**：每个入镜数值能在此次场景记录中找到。仿真回放、示例参数、算法输出有来源说明。片尾的交付状态与复盘一致。
- **封版**：在另一台普通电脑打开最终 MP4，检查音画同步、中文字体、字幕边界、片尾和实际分辨率。团队把交片文件、复剪工程、场景版本一并归档。
