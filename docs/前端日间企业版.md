# AERIS 企业版 · 日间与夜间

前端入口为 `apps/console`。本次在已有地图、天气、仪表、Agent 和本地执行链路上增加产品首页、工作台、引导式任务流程以及本地身份服务。默认入口 `/` 是产品首页。

## 本地启动与第一次使用

1. 在仓库根目录创建 Python 虚拟环境并运行 `python -m pip install -r services/assistant/requirements.txt`（包含本地调度所需SQLAlchemy等依赖）；已有环境可以复用。Node 依赖仍使用 `apps/console/package-lock.json`，本次没有新增前端运行依赖。
2. 进入 `apps/console`，首次运行 `npm ci`，然后运行 `npm run dev:all`。
3. 打开 `http://127.0.0.1:5174/`，点击“创建第一个任务”。首次启动会要求设置管理员姓名、邮箱和密码。没有预置账号或默认密码。密码至少10位并包含字母和数字。
4. 创建工作区后，系统回到原目标页。选择“场景联调”，选择场景、生成待审任务、核对参数并勾选确认，再运行本地任务。
5. 在结果页打开详情，可以看到实际规划结果、执行端 ACK、执行状态与最近30条审计事件；刷新页面仍从后端恢复记录。
6. 需要团队协作时，先在“账户与安全”完成管理员邮箱验证，再在“身份与访问 → 成员管理”创建邀请。

Python 不在默认位置时，在启动前设置 `AERIS_PYTHON` 为可用的 Python 可执行文件的完整路径。Vite 同源代理到本地 BFF 8012；无需单独启动8000端口的任务 API，也不需要 RDS、DCS、OBS 或其他云资源。

## 页面与数据连接

| 页面 | 作用 | 实际数据接口 |
| --- | --- | --- |
| `/` | 产品认知、单一主行动、模块入口、预留3D展示位 | 登录状态、身份服务策略 |
| `/login`、`/register` | 登录、管理员初始化、邀请/开放注册、MFA验证 | `/api/auth/*` |
| `/workspace` | 任务摘要、最近任务、模块状态、新手清单 | `/api/workspace/summary` |
| `/missions` | 场景任务、自定义规划列表、恢复输入草稿 | 工作区摘要、本地按用户隔离的输入草稿 |
| `/missions/new` 场景模式 | 定义任务→审核→运行→结果 | `/api/dispatch/proposals` → `/tasks/{id}/confirm` |
| `/missions/new` 自定义模式 | ENU参数→风险快照→规划→结果 | `/api/planning/tasks` → `/snapshots/from-scene` → `/plan` |
| `/missions/{uuid}` | 执行结果、原始审计、完整记录导出 | `/api/dispatch/tasks/{id}`，2.5秒更新 |
| `/missions/plan/{id}` | 规划版本、航点、余量可用性、记录导出 | `/api/planning/tasks/{id}/routes`、`/margin` |
| `/airspace` | 真实地图、定位、二维/三维、天气、地形、仪表、Agent | 保留已有 MapLibre、公开天气、地形流和助手接口 |
| `/airspace?task={uuid}` | 在地图中展示指定场景任务航线 | 从M3任务读取已返回的航点，使用已有ENU显示投影 |
| `/airspace?planTask={id}` | 在地图中展示自定义任务最新规划航线 | 从规划API读取最新航线；仿真坐标仍明确标记 |
| `/fleet` | 默认进入遥测模式，查看来源、过期状态和飞行参数 | `/api/telemetry/stream` |
| `/analytics` | 运行记录、任务证据、摘要与原始记录导出 | 同一任务库与规划API |
| `/identity/users`、`/identity/roles` | 邀请成员、调整角色与启用状态、权限矩阵、身份审计 | `/api/auth/users`、`/invitations`、`/roles`、`/events` |
| `/account` | 邮箱验证、TOTP MFA设置/关闭、个人权限 | `/api/auth/email/*`、`/mfa/*` |
| `/help` | 场景化操作指南与明确入口 | 静态说明，不使用全屏功能巡游 |

任务详情打开地图时会传递任务ID并加载该任务航线。M3任务ID也会作为助手查询上下文；地图上的助手生成路线仍属于独立预览，不能自动下发。

## 本地身份服务

- `AERIS_IDENTITY_DIR`：默认 `logs/identity`，相对后端启动目录。SQLite持久化账户、会话、限流及身份审计。
- `AERIS_REGISTRATION`：`invite`（默认，邀请注册）、`open`（开放注册，仅获得观察员角色）、`closed`（关闭注册）。首次管理员初始化不依赖开放注册。
- `AERIS_COOKIE_SECURE=1`：仅在配置HTTPS入口后使用。当前回环HTTP开发默认关闭Secure属性；会话始终使用HttpOnly、SameSite=Strict Cookie，不保存到localStorage。
- 密码使用随机盐与PBKDF2-SHA256；会话令牌和验证令牌在库中仅保存哈希。登录失败限流；成功登录清除相应失败计数。
- MFA使用真实TOTP动态口令，支持一次登录挑战和口令防重放。设置密钥在验证器中手动录入；当前没有自助恢复码或密码重置服务，请保管验证器。
- 成员权限/启用状态改变时，撤销其现有会话；禁止删除或降级最后一名启用的管理员。
- 所有有副作用的BFF接口要求 `X-Aeris-Request: 1`，同时保留回环Host/Origin校验。只隐藏按钮无法绕过后端权限。

### 邮箱验证与邀请如何交付

本地版本没有配置SMTP，不会宣称邮件已发送。初始化或重新生成验证令牌后，到运行电脑的 `logs/identity/outbox/*.json` 中找到 `to` 与目标邮箱一致、`kind=verify` 的最新记录，复制 `token` 到“账户与安全 → 邮箱验证”。验证令牌30分钟有效，重新生成会令旧验证令牌失效。

管理员创建邀请后，同一目录会生成 `kind=invite` 记录。将对应 `token` 交给被邀请成员，在 `/register` 使用绑定邮箱和邀请码注册。邀请48小时有效、绑定邮箱且只能使用一次。使用 `AERIS_IDENTITY_DIR` 时，以该目录下的 `outbox` 为准。

这是本地开发交付机制，不等同于企业邮件验证或统一身份平台。不要提交 `logs/identity`，不要把发件箱通过Web静态目录公开。未来接入SMTP/企业IdP应替换交付适配，不改变前端对“交付成功/失败”的真实性要求。

| --- | --- | --- | --- |
| 查看工作台、任务、地图、遥测和记录 | 是 | 是 | 是 |

## 数据与执行边界

1. 场景联调确实运行现有M3状态机、M2工具、独立校验及M4合成执行端；回执是合成执行端回执，不是PX4飞控回执。真实飞控是否接入以遥测来源与执行器配置为准。
2. 自定义任务确实写入独立任务API的SQLite、绑定场景风险快照并调用已配置的规划器。默认仍是该API的A*几何基线。页面不通过“算法名称”伪装切换到备降约束规划，也不补造缺失的能耗/余量。
3. 真实经纬度选点继续保存在地图任务草稿；不会用演示锚点把真实地点转换成已标定的可执行任务。任务航线地图叠加为ENU显示投影，界面明确标为仿真。
4. 飞控遥测配置由 `AERIS_TELEMETRY_FILE` 指定；未配置/过期时保留明确状态，不用演示数字补缺。
5. 地图默认使用CARTO Positron日间底图，卫星、DEM、天气功能保留。第三方瓦片/天气请求失败时仍显示既有离线与重试入口。没有新增地图服务Key。
6. 默认助手仍为本地工具规则模式。配置真实模型服务后才显示对应模型来源；本次没有开通或购买华为云资源。
7. 身份服务保护本地BFF与其挂载的规划接口；单独启动的8000端口开发API有自己的使用边界，不应作为绕过BFF的对外入口。

## 首页3D动画接入位

`apps/console/src/portal/LandingPage.tsx` 中 `#hero-model-slot[data-model-slot="hero"]` 是预留容器。保持外层 `.l-hero-visual`、悬浮信息卡和底部说明，把其中的 `SpatialCanvas` 组件替换为后续模型组件即可。当前城市、无人机和飞线为原生 SVG 视觉示意。

外层有响应式尺寸，桌面与手机会自动布局。模型组件应使用ResizeObserver适配容器、在卸载时释放渲染资源、在不可见或系统偏好减少动画时暂停，并保留加载失败时的静态图。此位置当前没有接入模型或假装识别真实地形。

## 配色与交互规范

首页采用大幅空间视觉、左侧价值说明和单一主行动，随后展示产品能力、场景切换及三步引导。设计融合团结引擎的首屏层级、Stripe的渐变分区及企业后台的导航逻辑；未复制第三方图片、视频或页面代码。

- 行动色统一为品牌蓝；空域用青绿、设备和智能助手用紫、记录入口用暖琥珀作为辅助色。警告/失败继续保留独立的语义状态。
- 工作台、任务步骤、地图仪表、助手、成员与账户页面采用同一套浅底、渐变、线条和卡片层级。重要正文与数值保持足够对比度，不用浅色装饰字承担核心信息。
- 首页场景支持点击和键盘方向键/Home/End切换；导航支持折叠、手机遮罩关闭和Esc关闭；任务支持保存草稿与稍后继续。
- 动画使用原生CSS/SVG，支持系统“减少动态效果”。首页动效不代表真实飞行或地形识别。

### 夜间模式

首页、登录页和工作区顶栏均提供月亮/太阳切换按钮；“账户与安全 → 界面外观”还可选择日间、夜间或跟随系统。新浏览器默认日间，跟随系统需要用户主动选择。夜间以深海军蓝为底、蓝灰卡片分层，品牌蓝用于主行动，青绿、紫和琥珀用于不同模块与状态；地图、仪表、路线预览、助手、弹窗和手机布局一并适配。

偏好保存在浏览器 `localStorage` 的 `aeris.theme.preference` 中，同源标签页即时同步；刷新与登录跳转会保留选择。它是浏览器偏好，不是服务器账户设置。禁用本地存储时仍可在当前页面切换。首屏脚本 `public/theme-init.js` 在渲染前应用主题以减少闪白。

标准地图会切换 CARTO Positron / Dark Matter 样式，保留同一地图实例与相机；卫星选择不会被主题覆盖。网络失败时回退到相应主题的离线底图。Three.js 地形仅更新材质、灯光、雾与颜色，不重新初始化地形和相机；主题改变不会修改DEM版本、航点、审核状态或飞控指令。

建议使用 Chrome / Edge 123+ 或其他支持 CSS `light-dark()` 的现代浏览器，确保原控制台的细分文字颜色与系统表单同步适配。

## 检查与测试

- `npm run build`：TypeScript与Vite生产构建。
- `npm test`：已有地图/天气/助手/遥测回归，以及首页、登录回跳、任务步骤、实际规划、草稿、导航、日夜切换、跟随系统与跨标签页同步等浏览器测试。测试身份库、任务库和调度目录隔离在 `logs/browser-tests`，不会使用正常账号数据。
- `python -m pytest`：核心后端、规划/校验、M3/M4、API及新增身份权限测试。
- `python -m ruff check .` 与前端 `npm run format:check`：格式与静态检查。

浏览器测试的截图 `apps/console/test-results/design-*.png` 可用于查看首页、工作台、登录、审核、结果和手机布局。该目录为测试产物，不应当作真实飞行效果证据。
