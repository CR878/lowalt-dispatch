# 接口契约 v0（2026-11-08 起草，待 11/10 三人确认冻结）

> **字段的权威定义在 `core/models.py`，本文只解释约定与坑。**
> 两者不一致时以代码为准，并且必须当天把本文改过来——文档跑偏比没文档更危险。

## 0. 为什么先冻结接口

三个人并行开发，最先崩的永远是接口而不是算法。飞控说"高度 30"，云端以为是海拔；规划说"能耗 80"，边缘以为是百分比——这类错误不会报错，只会让最后的结果全部作废。

所以本文的目的很窄：**定死单位、时间基准、缺失值处理，以及"这个数据算不算数"。**

## 1. 全局约定

| 项 | 约定 | 违反的后果 |
|---|---|---|
| 距离 | m | — |
| 时间 | UTC 的 `datetime`（带时区）；场景事件用"相对任务开始秒数" | 跨时区/夏令时对不上 |
| 能量 | Wh（不是 SOC 百分比） | 备降余量算不出来 |
| 速度 | m/s | — |
| 坐标系 | 仿真场景 v0 用**局部 ENU 米制**；接飞控必须转 WGS84 | 两种坐标混用 = 图全错 |
| 高度基准 | `amsl` / `agl` / `rel_takeoff` 三选一，**显式写在对象里** | 差一个地面高程就撞楼 |
| 缺失值 | 用 `None`，禁止用 `0` 或 `-1` 顶替 | 静默错误，最贵的那种 |
| 仿真标识 | 每个数据对象带 `provenance.is_simulated` | 材料表述失真 |

`Position` 在构造时会强制检查：`frame=enu_m` 就不能同时有经纬度，反之亦然。这是故意做成会抛异常的——**宁可启动失败，也不要带着错误基准起飞。**

## 2. 五类对象

### 2.1 Task（任务单）

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | str | 全局唯一，建议 `T-YYYYMMDD-序号` |
| `origin` / `destination` | Position | 起点/终点，带坐标与高度基准 |
| `payload_kg` | float ≥ 0 | 载荷 |
| `vehicle_type` | str | 对应 `scenarios/vehicles/*.yaml` 的 key |
| `initial_energy_wh` | float > 0 | 起飞时**可用**能量 |
| `reserve_energy_wh` | float ≥ 0 | 策略保留量 E_reserve，备降约束的基线 |
| `time_limit_s` | float \| None | 任务时限；None = 不限 |
| `provenance` | DataProvenance | 任务来源（演示任务也要标） |

**约定：字段不全时走确认流程，不允许猜。** 地点不明确就不给坐标，电池状态不明就问。

### 2.2 RiskSnapshot（风险快照）

| 字段 | 说明 |
|---|---|
| `snapshot_id` | 规划器与校验器必须读**同一个** id |
| `captured_at` / `valid_until` | 采集时刻 / 失效时刻 |
| `landing_sites[]` | 可用备降点，每个带时窗与 `occupied` 状态 |
| `events[]` | RiskEvent 列表 |
| `is_stale(now)` | 过期快照不得用于批准新路线 |

### 2.3 RiskEvent（风险事件）

| 字段 | 说明 |
|---|---|
| `kind` | `restriction_zone` / `wind` / `link_degradation` / `landing_site_change` / `battery_anomaly` |
| `geometry` | GeoJSON，基准随场景 |
| `alt_min_m` / `alt_max_m` | 高度带；两者都给时必须 min ≤ max |
| `effective_from` | **生效时刻。早于此刻进入该区域不算违规**——这是 S2 场景判定的核心 |
| `provenance` | 来源与是否仿真 |

### 2.4 RoutePlan（候选航线）

| 字段 | 说明 |
|---|---|
| `plan_version` | 同一任务每次改线递增（v1/v2/…） |
| `snapshot_id` | 生成它的快照；快照变了必须换版本 |
| `algorithm` | 产出算法名，评测时按这个分组 |
| `waypoints[]` | ≥ 2 个点 |
| `energy_budget_wh` | 能量预算 |
| `diversion_site_id` | 主备降点；None = 规划时没找到有效退出方案 |
| `checks[]` | **规划器自报**，仅供参考。独立校验器必须重新复算，不得只信这里 |

### 2.5 DiversionMarginProfile（备降余量剖面 —— 主视觉的数据契约）

| 字段 | 说明 |
|---|---|
| `samples[]` | 每个采样点 `{s_m, t_s, margin_wh, nearest_site_id}` |
| `margin_wh` | `E_left − E_reserve − E_need_to_nearest_valid_landing` |
| `negative_sample_count` | 负余量采样点数，评测要单独报这个 |
| `is_feasible` | 全程非负且样本非空才为 True |

`nearest_site_id = None` 表示该采样点**没有任何有效退出路径**——这是最严重的情况，不是 0 余量。

### 2.6 VehicleState / PlanCommand / PlanAck（执行三件套）

| 对象 | 关键字段 | 坑 |
|---|---|---|
| `VehicleState` | `executing_plan_version`、`flight_mode`、`link_quality_pct` | 拿不到剩余能量就留 None，别用 SOC 硬换算 |
| `PlanCommand` | `command_id`、`plan_version`、`expires_at` | 重试靠 `command_id` 去重；过期命令边缘端必须拒绝 |
| `PlanAck` | `accepted`、`reject_reason`、`fc_mode` | **没有 ACK 就不算执行成功**，页面上不能显示"已下发"完事 |

## 3. 服务动作（HTTP 契约的雏形）

首轮用固定样例即可，不等算法完成：

| 动作 | 入参 | 出参 |
|---|---|---|
| 创建任务 | Task 草稿 | Task |
| 获取风险快照 | task_id | RiskSnapshot |
| 规划候选路线 | snapshot_id, 约束 | RoutePlan[] |
| 校验路线 | RoutePlan, snapshot_id | ConstraintCheck[] |
| 提交执行请求 | RoutePlan | PlanCommand |
| 注入仿真事件 | RiskEvent | 事件回执 |
| 读取任务状态 | task_id | VehicleState + 执行版本 |
| 回放与导出 | task_id | 轨迹 + 事件时间线 + CSV |

## 4. 三条不能妥协的规则

1. **校验器不读规划器的 `checks`**。它按同一个 `snapshot_id` 独立复算，输出自己的 `ConstraintCheck[]`。
2. **云端恢复后先对账再下发**：比对飞控当前 `executing_plan_version` 与云端认为的版本，不一致就先同步状态，不直接推新计划。
3. **`is_simulated` 跟着数据走到底**。它进 CSV、进日志、进材料。任何一处在材料里把仿真写成实测，整个项目的可信度就没了。

## 6. 校验器输出契约（2026-11-09 新增）

M3 的 `agent.guards.report_failures()` 会**强制**检查这份报告，缺项直接判 `blocked`。
所以校验器必须按下面的约定输出，`validator/` 已实现，改动前先看这段。

### 6.1 必需检查项

`REQUIRED_CHECKS = ("restriction_zone", "clearance", "diversion_reachability", "energy")`
（定义在 `agent/contracts.py`）。任务带 `time_limit_s` 时**额外**要求 `time_limit`。

- 名字必须一字不差；重复的名字会被判"歧义"。
- 每项 `detail` 不能为空——评审要能直接引用它。
- 允许输出额外检查项（我们用 `endpoint_binding`、`payload_limit`），失败同样导致拒绝。

### 6.2 报告绑定

`ValidationReport` 必须带 `route_digest`，由 `core.models.route_digest(route)` 计算。
它绑定的是航线**内容**：航点改动一个坐标，摘要就变，旧报告立刻失效。

`route_digest` 放在 `core/models.py` 而不是 agent 里，是因为它是 `RoutePlan` 自身的属性，
规划侧与校验侧必须用同一份实现。agent 侧保留再导出，`from agent.contracts import route_digest` 仍可用。

### 6.3 时间窗

`verified_at` 必须落在本次校验调用的时间窗内（`not_before <= verified_at <= now`）。
复用一份旧报告会被 `report_time` 拒绝——报告不能跨次调用缓存。

### 6.4 事件与限制区的对应

`RiskEvent.event_id` **直接使用 zone_id**（例如 `R01`）。这样：
- 校验器按 id 就能取到几何（也支持从 `event.geometry` 读，两种都兼容）；
- 日志、报告、材料里说的都是同一个名字，不需要再维护一张映射表。

`planner/assemble.py::build_snapshot()` 负责把场景 yaml 里的相对时间 `at_s` 转成绝对
`effective_from`。**这一层转换必须留痕**，因为"限制区什么时候生效"是判断违规的关键前提。
