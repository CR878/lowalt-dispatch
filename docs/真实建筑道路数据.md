# 真实建筑与道路数据

真实模式读取 `services/assistant/osm_obstacles.py` 的 `fetch_obstacles`，返回独立的建筑 GeoJSON、道路 GeoJSON、来源元数据和警告。坐标始终是 WGS84 经度/纬度。冻结的 `scenarios/v0` 没有被覆盖，也不参与真实航线的障碍数据。

## 数据获取与失败行为

优先请求全球 Overpass 实例，查询建筑、建筑部件、建筑多面关系和道路。全球实例不可达时，使用 **OSM 主站 API 0.6 map 的真实数据**，并把来源改成 `OpenStreetMap / API 0.6 map`；不会把仿真矩形填入真实模式。备用下载至多两个并发、32次实际 HTTP 请求；小块下载和建筑关系 `/full` 都有超时。完整场景只有在所有请求和几何检查成功后才落盘。服务均失败时明确返回不可用。

原始小块存在忽略版本控制的 `scenarios/real/.tiles`，每块保留请求 URL、获取时间和 SHA256，可在6小时内恢复下载；只有全部覆盖完成才会生成 `scenarios/real/<scene_id>/metadata.json`。原始 XML 采用流式解析，避免把大范围地图的 DOM 全部留在内存。完整场景缓存最多24小时，按最早源数据获取时间检查，不会通过重新包装延长数据有效期。过期数据遇到网络失败也不返回。

完整场景保存 `obstacles.geojson`、`roads.geojson` 和 `metadata.json`。`load_cached_scene` 只接受16位十六进制标识，检查来源状态、时间、文件计数和覆盖范围的一致性；接口不会接受任意路径。

## 高度与坏拓扑

- `height_source=tag`：优先读取 OSM `height`，米为默认单位；显式英尺乘0.3048。这仍是地图标签，未经过独立测绘。
- `height_source=levels`：`building:levels × 3m`，明确标记 `height_estimated=true`，每层3米只是估算转换。
- `height_source=estimate`：没有可靠标签时 `height_m=null`，不填9米、默认楼高或其他看似真实的数字。

规划时保守避让所有建筑轮廓，不依赖估算高度进行越顶。道路只作地理参照，不是批准的飞行走廊。

若完整获取的真实节点存在自交、错误内外环等 OSM 拓扑问题，采用**全部已获取真实成员节点的凸包**作为不透明避让包络。该记录明确带 `geometry_status=derived_conservative`、`geometry_method=convex_hull_of_osm_member_nodes`、原因和原始成员角色/坐标，元数据也统计数量并返回警告。它是从真实坐标派生的近似区域，不是实测建筑轮廓。如果网络或节点坐标缺失，则拒绝导入，不能用凸包填补缺失的数据。

## 本次真实抓取证据

2026-11-17 获取的上海虹桥—浦东外包框缓存为 `4bac5ae2d8f14590`，WGS84 bbox 为 `[121.324675,31.135373,121.814934,31.20696]`。采用20个主站 map 小块及2个完整建筑关系，源请求 URL、SHA256 和时间均在 `metadata.json` 可查。

实际取得27,971条建筑记录、22,165条道路记录；建筑高度109条来自 `height`，890条来自层数估算，26,972条高度未知；4条坏拓扑使用明确标注的真实节点凸包。所有数字是这次获取结果，不是程序默认值。

`results/osm_height_audit.json` 随机抽取5栋带 `height` 的建筑，另行联网读取主站原始标签复核，40/120/15/18/279米全部一致。抽样种子和复查 URL 已记录；该检查仅证明程序与OSM标签一致，不证明高度已实测。

刷新命令：

```powershell
.venv/Scripts/python.exe -m services.assistant.osm_obstacles --origin 121.335209 31.197950 --destination 121.804400 31.144383 --refresh
```
