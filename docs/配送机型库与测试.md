# 配送机型库与参数测试

入口：登录后侧栏“配送机型库”（`/aircraft`）。可以选择厂家机型，查看来源和适用条件，或手动录入、导入 JSON、编辑、删除、导出自己的测试档案。所选机型会保留到空域态势的真实航线面板；工单载荷也会带入评估。当前自定义档案保存在本浏览器 localStorage，不会自动同步到其他浏览器或团队成员。

## 手动测试档案

必填名称、来源说明、最大载荷和测试巡航空速。可选最大速度、参考航程、标称电量、实际可用电量、策略保留量、巡航 Wh/m、抗风和温度区间。未知值留空，不填零代替。页面可下载空白 JSON 模板；导入文件上限 64 KB，最多保存 20 款本机档案。

所有手工输入（包括填写了手册 URL 或测试日志号的数据）均为 `user_supplied_test`。接口拒绝伪造 `calibrated_at`、非有限值、负能耗、巡航速度大于最大速度、可用电量大于标称电量、保留量不小于可用电量、颠倒温度范围、未知字段或同时选择两种机型。

## 计算含义

“运行参数测试”使用用户填写的单程距离、载荷与恒定风场情景，明确区分无风、顺风、逆风、侧风，**不是天气预报**。只比较载荷与公布载荷上限、距离与参考工况航程、测试风与公布抗风值。`within_reference` 只表示数值落在参考范围；缺失值为 `unavailable`，超出为 `exceeded`。不同工况的指标不能组合为飞行承诺。

时间用风三角计算：`Vg = sqrt(Va² - Wcross²) + Walong`，`t = distance / Vg`。厂家机型使用明确标注的参考速度作为测试输入，自定义机型使用用户填写空速。只有填写 Wh/m 后才计算恒功率测试能耗：`E = e_Wh/m × Va × t`。同时填可用电量与保留量时，显示 `usable - reserve - E` 的预算余量，负值明确标出。

真实航线仍先做 OSM 建筑避障，结果附带所选机型的完整来源快照与实际绕障长度的规格对照。自定义 Wh/m 齐备且真实 Open-Meteo 预报完整时，也可以按航段风场计算条件测试时间与能耗，标记 `user_test`；天气缺失则不计算。改换机型、载荷或起飞时间后，页面提示重算旧结果。

这些测试不包含起降、转弯、返航、备降、载荷变化和电池老化。Wingcopter 的倾转过渡、固定翼最小转弯半径也尚未建模。几何路线仍是水平参考，`operationally_approved` 和 `dispatch_enabled` 均为 false。

## API 与验证

- `GET /api/assistant/vehicles`：厂家目录及来源。
- `POST /api/assistant/vehicles/validate`：校验一个自定义档案，不落盘到服务器。
- `POST /api/assistant/vehicles/evaluate`：`vehicle_key` 或 `custom_vehicle`，以及 `payload_kg`、`distance_km`、`wind_speed_mps`、`wind_direction`。
- `POST /api/assistant/navigation/candidates`：WGS84 请求新增 `custom_vehicle` 和 `payload_kg`；目录选择使用 `vehicle_key`。

所有 API 沿用现有登录、角色权限与同源标记校验。单元测试合成参数只用于验证公式；不能引用为真实机型数据。

```powershell

cd apps/console
npm run format:check

npx playwright test tests/aircraft.spec.ts tests/real-routing.spec.ts --timeout=180000
```
